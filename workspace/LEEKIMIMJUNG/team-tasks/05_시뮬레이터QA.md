# 시뮬레이터/QA 담당 — (담당자 미배정, PM 임제민 조율 + 전원 참여 권장)

> 8명 역할표에 별도 QA 인원이 없습니다. 각 함수 다 짠 사람이 자기 파트 테스트하고, 마지막엔 전원이 리그레션에 참여하는 걸 추천합니다.

---

## 1. 시작하기 전에 알아야 할 것

### 기본 지식
- 터미널에서 `npm run` 명령어 실행하는 법
- JSON 파일 읽는 법 (제출 파일, validate 결과 리포트가 다 JSON)
- "정상 케이스"와 "오류 케이스"를 구분해서 테스트한다는 개념 (일부러 규칙 위반하는 입력도 넣어봐야 함)

### 이 프로젝트만의 핵심 개념
- **우리가 시뮬레이터를 만드는 게 아닙니다.** 공식 시뮬레이터(`apps/simulator-web`+`apps/simulation-api`)에 우리 제출물을 넣고, 통과하는지 확인하는 역할입니다.
- 검증 도구는 이미 다 있음 — `npm run participant:validate`, `npm run participant:package`. 직접 검증 스크립트를 새로 짤 필요 없고, 이 명령어들을 **언제/어떤 케이스에** 돌릴지 관리하는 역할입니다.
- `actualDeviceCommandSent: false`, `validationMode: "SIMULATION_ONLY"`, `executionEnvironment: "DIGITAL_TWIN"` 3개는 모든 제출물에 항상 고정으로 들어가야 하는 안전 필드입니다.

---

## 2. 시작 순서

### 1단계 — 워크: 정상·오류 테스트 시나리오 작성
9개 함수가 어느 정도(3~4개라도) 완성되면 바로 시작 가능. 전체 완성될 때까지 기다릴 필요 없음.

| 태스크 | 내용 |
|---|---|
| 병원 정상 시나리오 4개 이상 작성 | CLAUDE.md의 5개 페르소나 기준으로 입력값 세트 작성 |
| 병원 오류 시나리오 작성 | 일부러 증상 기반 매칭 시도하는 등 금지 케이스 입력값 작성 |
| 자유 시나리오 1개 작성 | 팀 창의 시나리오 |
| 시나리오별 기대 결과 정리 | 어떤 입력이면 PASS/FAIL인지 표로 정리 |
| 시나리오 문서화·공유 | 팀 공유 |

### 2단계 — 워크: 안전 필드·금지 Action 검증
| 태스크 | 내용 |
|---|---|
| actualDeviceCommandSent:false 검증 | 모든 제출물에서 항상 false인지 확인 |
| validationMode/executionEnvironment 검증 | 고정값 확인 |
| 결제/접수/민원 금지 Action 0건 검증 | `forbiddenActions` 목록과 대조 |
| 검증 실패 리포트 포맷 정의 | 오류코드별로 어디 고쳐야 하는지 정리 |
| 수동 실행 가이드 문서화 | `npm run participant:validate` 사용법 팀 공유 |

### 3단계 — 워크: validate/package 실행 및 산출물 관리
| 태스크 | 내용 |
|---|---|
| validate 결과(json/report) 수집 | 실행 로그 보관 |
| package 실행 및 산출물 보관 | `npm run participant:package -- --team LEEKIMIMJUNG --file <파일>` |
| 제출 파일 버전 관리 | 날짜/시도별로 파일 구분해서 보관 |
| 산출물 공유 폴더 정리 | 팀 공유 위치에 정리 |
| 최종 제출 파일 확정·백업 | 마감 직전 확정본 백업 |

### 4단계 — 워크: 최종 제출 전 리그레션 테스트 (마감 직전, 전원 참여)
| 태스크 | 내용 |
|---|---|
| 9개 함수 통합 파이프라인 실행 테스트 | `buildSubmission()` 전체 실행 |
| 5개 시나리오 전체 재실행 확인 | 이전에 통과했던 케이스가 여전히 통과하는지(회귀 확인) |
| validate --execute PASS 확인 | 최종 검증 |
| 회귀 발생 시 담당자 전달 | 어떤 함수 고쳐야 하는지 담당자에게 전달 |
| 최종 제출 전 체크리스트 작성 | CLAUDE.md 완료 체크리스트와 대조 |

---

## 3. 참고
```bash
npm run participant:progress -- --team LEEKIMIMJUNG            # 진행률
npm run participant:validate -- --file <출력파일> --execute     # 검증
npm run participant:package -- --team LEEKIMIMJUNG --file <파일> # 제출 패키징
```
