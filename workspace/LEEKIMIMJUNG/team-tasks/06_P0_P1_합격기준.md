# KioBridge 병원 참가팀 MVP 요건 — LEEKIMIMJUNG

> 이 문서는 발표자료용 P0/P1/제외범위 정리입니다. 형식은 참고 예시(치킨집 실기기 트랙)에서 빌려왔고, 내용은 저희 병원·시뮬레이션 프로젝트 기준으로 새로 작성했습니다.

## 개요

| 항목 | 내용 |
|---|---|
| 서비스 소개 | 병원 키오스크 개인화 판단 엔진 — 프로필·추천·승인 UX를 만들고, 공식 KioBridge 시뮬레이터가 이를 가상 키오스크에서 검증 |
| 최종 목표 | 대표 프로필(예: 초진·예약없음·큰글씨) 1건이 입력→추천→이유확인→승인→디지털 트윈 실행까지 `SIMULATION_ONLY`로 끝까지 통과 |
| 확보 자산 | 공식 시뮬레이터(`apps/simulator-web`+`apps/simulation-api`), 병원 fixture(후보 6개), `@kiobridge/participant-sdk`, 검증 도구(`participant:validate`) |
| 참가팀 핵심 역할 | 사용자 프로필·세션맥락·매칭·설명·승인·실행계획 9개 함수(`participant.ts`)와 이를 공식 API로 실제 제출하는 연동 코드 구현 |
| 범위 원칙 | 실제 키오스크·실제 Agent·실제 결제는 대상이 아님(`SIMULATION_ONLY`/`DIGITAL_TWIN`) — 안전한 디지털 트윈 왕복 검증이 P0 |

## 개발 범위 구분

| 구분 | 내용 | 담당 | 완료 판단 |
|---|---|---|---|
| 플랫폼 제공 자산 | 공식 시뮬레이터, 병원 fixture, SDK, 검증 CLI | KioBridge(운영진) | 우리는 재개발 금지 (`packages/`,`apps/`,`environments/`,`schemas/`) |
| 참가팀 필수 개발 | 9개 함수 + Simulation API 연동 + 화면 2개(수집/승인) | 우리 팀 8명 | P0 항목이 `npm run participant:validate --execute` PASS로 연결 |
| 최종 확인 | validate 실행, Evidence 확인, 리그레션 | PM(임제민)+전원(QA) | PASS/FAIL 기록, 8/15 자정까지 |

## 참가팀 P0 — 반드시 구현할 9개

| 번호 | P0 요건 | 담당 함수 | 구현 기준 | 합격 기준 |
|---|---|---|---|---|
| P0-1 | 정보 수집 | `collectProfile` | 로그인 없이도 동작, 실제 개인정보 금지, 자동입력값은 확인받기 | 비회원 경로로 입력→다음단계 진행 가능 |
| P0-2 | 공식 형식 변환 | `mapToCanonicalInput` | `UserProfile` 스키마 준수, UTC 타임스탬프, enum만 사용 | `SCHEMA_INVALID`/`ENUM_VALUE_INVALID` 0건 |
| P0-3 | 세션 맥락 구성 | `createSessionContext` | facts/preferences/hardConstraints/capabilities 섹션 구분 | `DOMAIN_CONTEXT_MISMATCH` 0건 |
| P0-4 | Hard Constraint 필터링 | `filterCandidates` | 위반 후보 완전 제거(감점 아님), `available=false` 제외 | 위반 후보가 추천에 절대 안 나옴 |
| P0-5 | 추천 순위 결정 | `recommend` | 증상 기반 진료과 추론 금지, 조건 조합만으로 판단(하드코딩 금지) | 5개 시나리오 각각 규칙에 맞는 후보 산출 |
| P0-6 | 추천 이유 설명 | `explainRecommendation` | 최소 1개 문장, "AI가 추천" 등 금지문구 없음 | 이유가 비어있지 않고 사용한 정보 명시 |
| P0-7 | 사용자 승인 | `collectUserDecision` | 수락/거절/다른후보/다시입력 4경로, 승인 없이 진행 금지 | `ACTIONS_WITHOUT_APPROVAL` 0건 |
| P0-8 | 실행계획 생성 | `buildExecutionPlan` | fixture transitions 그대로, verifier로 정지, 결제/확정 Action 금지 | `FORBIDDEN_ACTION`/`MISSING_VERIFIER` 0건 |
| P0-9 | 공식 API 제출·검증 | Simulation API 연동 | 세션생성→제출→검증→Evidence 왕복 | `npm run participant:validate --execute` PASS |

## P1 — 여유 되면 (필수 아님)

| 항목 | 내용 | 진행 조건 |
|---|---|---|
| 5개 시나리오 전체 커버 | 시각장애아동/청각장애/고령자/학생/공황장애 전부 매칭 검증 | P0 완료 후 |
| 대안(2~3순위) UX 고도화 | `buildAlternatives` 결과를 풍부하게 화면에 표시 | P0 완료 후 |
| 접근성 심화 검증 | 200%확대, 키보드전용, 색맹 시뮬레이션 등 수동 테스트 확장 | 여유 있으면 |
| 디지털 트윈 재생 화면 연동 | 승인 후 공식 시뮬레이터 재생/Evidence 화면 링크 | 백엔드 API연동 끝난 후 |

## 제외 범위 (우리는 절대 안 함)

| 항목 | 이유 |
|---|---|
| 실제 키오스크 클릭·실제 Agent 연결 | CLAUDE.md 절대 원칙 — `SIMULATION_ONLY`만 |
| 실제 결제·실제 병원 접수 완료 | 플랫폼 레벨에서 `forbiddenActions`로 차단, 계획에 넣기만 해도 FAIL |
| 증상 기반 진료과 자동매칭 | 병원 환경 전용 금지 규칙 (의료 판단으로 간주됨) |
| 시뮬레이터 자체 재구현, 상태머신 재구현, 자체 스키마 설계 | 플랫폼이 이미 제공, 우리는 `packages/`,`apps/`,`environments/`,`schemas/` 수정 금지 |

## 최종 합격 기준

| 구분 | 검증 항목 | 증거 | 합격 기준 |
|---|---|---|---|
| 기능 | 대표 프로필 → 승인 → 실행계획 → Evidence | `npm run participant:validate --execute` 로그 | 리그레션 3회 이상 연속 성공 |
| 정확성 | 추천 후보 매칭 | 세션 로그(`recommendedCandidateId`) | facts와 후보 `supportedOptions` 일치 |
| 정확성 | 진료과 선택 | `sessionContext.facts.departmentId` | 사용자 응답값만 사용, 자동추론 0건 |
| 안전 | 결제/접수확정 경계 | `forbiddenActions` 검증 로그 | 결제·접수확정 Action 0건 |
| 안전 | 시뮬레이션 고정 필드 | 제출 JSON | `actualDeviceCommandSent:false` 등 항상 고정 |
| 실패 | UNKNOWN 처리 | STOP/재확인 로그 | 오류 후 임의 진행 0건 |
| P1 | 5개 시나리오 확장 검증 | 시나리오별 리포트 | P0 합격과 분리, 여유 있을 때 |
