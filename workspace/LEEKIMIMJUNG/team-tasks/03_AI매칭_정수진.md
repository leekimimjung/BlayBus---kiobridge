# AI/매칭엔진 담당 — 정수진 (+ 임제민 보조)

---

## 1. 시작하기 전에 알아야 할 것

### 기본 지식
- TS/JS 기초 문법, 배열 메서드(`filter`, `map`, `sort`, `reduce`) — 점수 계산·정렬에 계속 씀
- **"AI"라고 해서 모델/LLM이 필요한 게 아닙니다.** 조건 매칭 + 점수 계산하는 일반 로직이면 충분합니다.

### 이 프로젝트만의 핵심 개념
- 우리가 만드는 건 `workspace/LEEKIMIMJUNG/src/participant.ts` 안의 **4개 함수**뿐: `filterCandidates` → `recommend` → `explainRecommendation` → `buildAlternatives`. 이 순서 그대로 파이프라인에서 실행됨.
- 입력으로 받는 `Candidate[]`(fixture.candidates 6개)와 `SessionContext`는 이미 백엔드팀(STEP3)이 만들어서 넘겨줌 — 타입만 보고 먼저 시작 가능, 완성 기다릴 필요 없음(mock 데이터로 선작업 가능).

### 🚨 가장 먼저 읽어야 할 것 — 병원 환경 절대 금지 규칙
- **증상으로 진료과 추론 절대 금지.** "무릎 아프다" → 정형외과 자동매칭 ❌. 진료과는 사용자가 직접 말한 값만 사용, 모르면 `UNSPECIFIED` 또는 직원 도움 경로.
- 진단·치료 추천·응급도 판단 금지, `departmentId` UNKNOWN인데 특정 과 자동 선택 금지
- fixture의 `HOSPITAL_DEPARTMENT_COMPATIBILITY` 규칙 자체가 "증상 기반 추론 금지"로 명시돼 있음

### 병원 후보(candidates) 6개 — 외워두면 편함
| ID | 이름 | 방문유형 | 예약 | 진료과 |
|---|---|---|---|---|
| HOS-001 | 예약 재진 접수 | REVISIT | HAS_APPOINTMENT | INTERNAL_MEDICINE |
| HOS-002 | 예약 초진 접수 | FIRST_VISIT | HAS_APPOINTMENT | ORTHOPEDICS |
| HOS-003 | 비예약 초진 안내 | FIRST_VISIT | NO_APPOINTMENT | UNSPECIFIED |
| HOS-004 | 건강검진 안내 | HEALTH_SCREENING | HAS_APPOINTMENT | HEALTH_SCREENING |
| HOS-005 | 검사 예약 확인 | EXAM | HAS_APPOINTMENT | RADIOLOGY |
| HOS-006 | 직원 도움 요청 | 전체 지원 | NO_APPOINTMENT | UNSPECIFIED |

### 하드코딩 절대 금지
같은 매칭 엔진이 조건 조합(`facts`/`preferences`/`hardConstraints`)만으로 다른 결과를 내야 합니다. "이 사람이면 이 후보" 식 페르소나별 if문 금지 — 아래 5개 시나리오는 전부 **조건 매칭 결과**로 자연스럽게 나와야 함.

## 2. 시작 순서

### 0단계 — mock 데이터로 먼저 시작
백엔드팀의 `createSessionContext()` 완성을 기다리지 말고, `SessionContext` 타입 모양의 mock 객체를 직접 만들어서 먼저 로직 작성 시작.

### 1단계 — 워크: Hard Constraint 필터링 (`filterCandidates`)
| 태스크 | 내용 |
|---|---|
| Hard Constraint 필터 규칙 정의 | `medicalInferenceAllowed` 등 절대조건 규칙표 작성, 위반 기준 정리 |
| Hard Constraint 필터 로직 구현 | `candidates.filter()`로 위반 후보 완전 제거 (감점 아님, 제거) |
| available=false 후보 제외 로직 구현 | 이용불가 후보 필터링 |
| 제외 사유 기록 로직 구현 | 3단계 설명 문구에 쓸 제외 사유 저장 |
| 필터링 단위 테스트 작성 | 위반/비위반 케이스별 테스트 |

### 2단계 — 워크: 추천 순위 매칭 로직 (`recommend`)
| 태스크 | 내용 |
|---|---|
| 병원 도메인 매칭 규칙 정의 | `facts`(visitType/appointment/department) 기준 매칭 조건표 |
| 유사도 랭킹 가중치 설계 | preferences/facts별 점수 배점 설계 |
| 유사도 랭킹 알고리즘 구현 | 점수 계산 후 정렬해 1순위 산출 |
| 신뢰도 낮을 때 재질문 트리거 구현 | `requiresReconfirmation: true` 처리 |
| 충족/미충족 선호 태깅 로직 구현 | `unmetConditions` 필드 채우기 |

### 3단계 — 워크: 추천 이유 설명 (`explainRecommendation`)
| 태스크 | 내용 |
|---|---|
| 추천 이유 문장 생성 로직 구현 | 최소 1개, 사용한 사용자 정보 명시 |
| 제외 조건 설명 로직 구현 | 왜 다른 후보가 빠졌는지 문장화 |
| 병원 시나리오별 문구 템플릿 작성 | 아래 5개 시나리오 기준 예시 문장 |
| 금지 문구 필터링 | "AI가 추천했습니다" 등 문구 안 나오게 검수 |
| 매칭 결과 테스트 및 튜닝 | 실제 시나리오로 문장 품질 검증 |

### 4단계 — 워크: 대안 제시 (`buildAlternatives`)
| 태스크 | 내용 |
|---|---|
| 대체 후보 2~3순위 산출 로직 구현 | recommend 결과 기반 차순위 추출 |
| 대안 hardConstraint 검증 로직 | 대안도 절대조건 지키는지 확인 |
| 제외 후보 재등장 방지 로직 | filterCandidates에서 뺀 후보 다시 안 나오게 |
| 대안 후보 ID 목록 반환 형식 맞추기 | `alternativeCandidateIds` 타입 준수 |
| 대안 로직 단위 테스트 작성 | 대안 있음/없음 케이스 테스트 |

### 5단계 — 5개 시나리오로 전체 파이프라인 검증
1. 시각장애 아동 — 초진, 예약없음, 음성안내, 보호자없음 → 안전장치(직원호출) 필수
2. 청각장애 환자 — 초진, 예약없음, 청각지원 → 화면 시각 알림으로 대체
3. 재진 고령자 — 재진, 예약있음, 큰글씨 → **HOS-001**
4. 무릎통증 학생 — 초진, 예약없음 → 진료과는 사용자가 직접 선택한 값만 사용 (`UNSPECIFIED`/`UNKNOWN`이면 **HOS-003** 또는 재확인, 자동매칭 절대 금지)
5. 공황장애 환자 — 재진, "천천히 진행 모드" → 추천 이유 문구에 관련 안내 포함 가능 (화면 전환 자체는 프론트 담당)

### 6단계 — 통합 확인
```bash
npm run participant:progress -- --team LEEKIMIMJUNG
```
