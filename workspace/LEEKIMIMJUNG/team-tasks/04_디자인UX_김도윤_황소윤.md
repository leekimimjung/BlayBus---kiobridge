# 디자인/UX 담당 — 김도윤, 황소윤

---

## 1. 시작하기 전에 알아야 할 것

### 기본 지식
- 와이어프레임/목업 툴 아무거나 (피그마, 손그림+사진도 무방) — 코드 작성 없음
- 접근성 디자인 원칙: 색상 대비, 색상만으로 상태를 구분하지 않기(아이콘/텍스트 병행), 큰글씨 대응 레이아웃, 간단한 문장

### 이 프로젝트만의 핵심 개념
- **증상 질문 절대 금지** — 진료과를 물을 때 "어디가 아프세요?" 같은 문구/화면 설계 자체를 만들면 안 됨. "어느 과로 오셨어요? 모르시면 일반안내로 도와드릴게요" 방향으로 설계
- **"AI가 추천했습니다" 같은 문구 금지** — 추천 이유는 항상 구체적인 문장으로 노출되는 화면이어야 함 (예: "예약 없이 오신 초진이시고 진료과를 말씀 안 하셔서...")
- **로그인은 선택** — 로그인 화면과 비로그인(건너뛰기) 화면 둘 다 필요
- 우리가 만드는 시안은 프론트팀(조은빛, 여윤우)이 그대로 코드로 옮길 화면이라는 점 — 실제 구현 가능한 컴포넌트 단위로 쪼개서 설계하면 좋음

## 2. 시작 순서

### 0단계 — 전체 화면 플로우 설계
공식 병원 fixture의 화면 흐름(`WELCOME → VISIT_TYPE → APPOINTMENT_CHECK → DEPARTMENT_SELECTION → ACCESSIBILITY_SUPPORT → CHECKIN_REVIEW → STOP`)을 참고해서, 우리 서비스 자체의 화면 흐름(정보수집 → 추천 → 이유확인 → 승인)을 스케치. 이게 이후 모든 작업의 기준이 됨.

### 1단계 — 비로그인 진입 경로 + 로그인 시 개인화 진입 경로 각각 설계
- "로그인 없이 이번만 이용" 버튼이 첫 화면에 명확히 보이는 시안
- 로그인 시엔 이전 접근성 설정 불러와서 보여주고 확인받는 흐름 (자동으로 채우고 넘기면 안 됨)

### 2단계 — 접근성 UI 가이드 정의
프론트팀이 참고할 체크리스트 문서로 정리:
- 큰글씨 모드일 때 최소 폰트 크기
- 색상 대비 기준
- 색상 없이도(흑백으로도) 상태 구분되는 방식 (예: 아이콘+텍스트 병행)
- 키보드 포커스 순서 원칙

### 3단계 — 병원 시나리오별 화면 목업 (5개)
1. 시각장애 아동 — 초진, 예약없음, 음성안내, 보호자없음 → 안전장치(직원호출 버튼) 눈에 띄게
2. 청각장애 환자 — 초진, 예약없음, 청각지원 → 소리 대신 크고 명확한 시각 알림
3. 재진 고령자 — 재진, 예약있음, 큰글씨 → 완료 후 처음 화면으로 리셋되는 흐름
4. 무릎통증 학생 — 초진, 예약없음 → 진료과 직접 선택 UI (증상 질문 없이)
5. 공황장애 환자 — 재진, "천천히 진행 모드" → 화면 전환 느리게, 단계마다 재확인 문구("괜찮으세요? 다음으로 넘어갈까요?"), 조용한 대기공간 안내

### 4단계 — 추천 이유(XAI) 표시 UI 설계
- 충족/미충족 선호를 구분해서 보여주는 방식 (예: 체크 아이콘=충족, X 아이콘=미충족)
- 대안(2~3순위) 제시 UI — "다른 것 보기" 버튼과 그 결과 화면

### 5단계 — 프론트팀에 전달
화면별로 캡처/링크 정리해서 `01_프론트엔드_조은빛_여윤우.md`의 단계(1~5단계)에 맞춰 순서대로 전달.
