# 디자인/UX 담당 — 김도윤, 황소윤

---

## 1. 시작하기 전에 알아야 할 것

### 기본 지식
- 와이어프레임/목업 툴 아무거나 (피그마, 손그림+사진도 무방) — 코드 작성 없음
- 접근성 디자인 원칙: 색상 대비, 색상만으로 상태를 구분하지 않기(아이콘/텍스트 병행), 큰글씨 대응 레이아웃, 간단한 문장

### 이 프로젝트만의 핵심 개념
- **증상 질문 절대 금지** — 진료과를 물을 때 "어디가 아프세요?" 같은 문구/화면 설계 자체를 만들면 안 됨. "어느 과로 오셨어요? 모르시면 일반안내로 도와드릴게요" 방향으로 설계
- **"AI가 추천했습니다" 같은 문구 금지** — 추천 이유는 항상 구체적인 문장으로 노출되는 화면이어야 함
- **로그인은 선택** — 로그인 화면과 비로그인(건너뛰기) 화면 둘 다 필요
- 우리가 만드는 시안은 프론트팀(조은빛, 여윤우)이 그대로 코드로 옮길 화면 — 실제 구현 가능한 컴포넌트 단위로 쪼개서 설계

## 2. 시작 순서

### 0단계 — 워크: 전체 화면 플로우 설계
| 태스크 | 내용 |
|---|---|
| 병원 fixture 흐름 참고해 플로우 스케치 | `WELCOME → VISIT_TYPE → APPOINTMENT_CHECK → DEPARTMENT_SELECTION → ACCESSIBILITY_SUPPORT → CHECKIN_REVIEW` 참고해 자체 흐름 스케치 |
| 단계별 화면 목록 정리 | 정보수집 → 추천 → 이유확인 → 승인 화면 리스트업 |
| 화면 전환 규칙 정의 | 뒤로가기/건너뛰기 등 |
| 플로우차트 제작 | 프론트팀 공유용 |
| 플로우 리뷰·피드백 반영 | 팀 검토 후 수정 |

### 1단계 — 워크: 비로그인/로그인 진입 경로 설계
| 태스크 | 내용 |
|---|---|
| 비로그인 "이번만 이용" 화면 설계 | 첫 화면에 명확히 노출 |
| 로그인 시 정보 확인 화면 설계 | 자동 불러온 값 확인받는 UI, 임의로 채워서 바로 넘기지 않기 |
| 로그인/비로그인 전환 UX 설계 | 버튼 위치·문구 |
| 자동 불러온 값 확인 패턴 정의 | 확인 없이 진행되는 패턴 방지 |
| 두 경로 접근성 기준 반영 검토 | 공통 체크리스트 적용 |

### 2단계 — 워크: 접근성 UI 가이드 정의
| 태스크 | 내용 |
|---|---|
| 색상 대비 기준 정의 | 배경/텍스트 대비 최소 기준 |
| 큰글씨 모드 최소 폰트 크기 정의 | 일반/큰글씨 모드 각각 px 기준 |
| 색상 없이 상태 구분 패턴 정의 | 아이콘+텍스트 병행 규칙 |
| 키보드 포커스 순서 원칙 정의 | 탭 이동 순서 규칙 |
| 가이드 문서화·프론트팀 전달 | 체크리스트 형태로 정리 |

### 3단계 — 워크: 병원 시나리오별 화면 목업 (5개)
| 태스크 | 내용 |
|---|---|
| 시각장애 아동 시나리오 목업 | 초진·예약없음·음성안내·보호자없음 → 직원호출(안전장치) 강조 |
| 청각장애 환자 시나리오 목업 | 초진·예약없음·청각지원 → 소리 대신 크고 명확한 시각 알림 |
| 재진 고령자 시나리오 목업 | 재진·예약있음·큰글씨 → 완료 후 처음 화면 리셋 흐름 |
| 무릎통증 학생 시나리오 목업 | 초진·예약없음 → 진료과 직접 선택 UI(증상질문 없이) |
| 공황장애 환자 시나리오 목업 | 재진·"천천히 진행 모드" → 느린 전환, 단계별 재확인 문구, 조용한 대기공간 안내 |

### 4단계 — 워크: 추천 이유(XAI) 표시 UI 설계
| 태스크 | 내용 |
|---|---|
| 충족/미충족 표시 아이콘 설계 | 체크/X 아이콘 등 |
| 대안(2~3순위) 제시 UI 설계 | "다른 것 보기" 버튼과 결과 화면 |
| 추천 이유 문장 노출 스타일 설계 | 위치·강조 방식 |
| 금지 표현 안 쓰는 톤 가이드 작성 | "AI 추천", "최적의 선택" 등 지양 문구 |
| 프론트팀 전달용 컴포넌트 스펙 정리 | 개발 참고용 스펙 문서 |

### 5단계 — 프론트팀에 전달
화면별 캡처/링크를 `01_프론트엔드_조은빛_여윤우.md`의 1~2단계 순서에 맞춰 전달.
